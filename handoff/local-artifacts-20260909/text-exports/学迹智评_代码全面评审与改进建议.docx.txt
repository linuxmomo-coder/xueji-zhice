一、执行摘要
结论：当前仓库是一个视觉完成度较好的 MVP 原型和工程骨架，适合继续迭代验证产品方向，但尚不具备直接承载真实学生数据、真实家长账号和生产题库的条件。当前最大的风险不是界面，而是身份与数据边界、演示接口与生产接口混用、数据库迁移缺失、测试覆盖不足。
二、评审范围与方法
本次检查了仓库源码、README、设计文档、CI 配置、数据库模型、API、前端页面、Docker Compose 与 Nginx 配置，并执行了后端测试、前端构建、后端健康接口、学生端接口和本地浏览器界面冒烟测试。仓库规模约 40 个受 Git 管理文件、约 4,814 行文本，其中 Markdown 约 3,358 行、Python 约 756 行、TSX/CSS 约 447 行。
三、必须优先修复的问题（P0）
3.1 角色切换不是安全权限
前端 App.tsx 中的角色切换仅修改 React state，并通过 /dashboard/{role} 选择页面内容。后端没有认证中间件，也没有基于用户、家庭、学生关系的授权依赖。当前“学生端/家长端/后台管理端”是 UI 视图，不是安全边界。任何能访问接口的人都可能直接调用学生列表、创建学生、确认资料和生成报告。
改进：建立 User、Family、Membership、StudentGuardian、Session 五类基础模型；所有业务接口通过 CurrentUser 和 Policy 依赖做授权；后台题库接口必须单独的 admin scope；确认 OCR 资料必须校验当前家长与 student_id 的关系；拒绝只从前端传入 role 作为可信依据。
3.2 演示接口和生产接口混在同一入口
/documents/demo-ocr、/practice-sessions/demo、/reports/demo 直接写入数据库或返回固定演示结果；应用启动时通过 lifespan 执行 seed_demo_data。README 已明确这些是演示能力，但生产部署路径仍会启动它们，容易造成演示数据污染、误把模拟 AI/OCR 当成真实服务。
改进：将 demo 路由放入 DemoRouter，仅在 APP_ENV=development 且显式 ENABLE_DEMO=true 时注册；生产环境禁止启动演示 seed；真实上传、OCR、报告、练习接口使用独立 service 层和异步任务状态。
3.3 默认密钥和默认密码不应可用于生产
配置和 Compose 中存在 change-me-in-production、change-me 等兜底值。即使 README 提醒修改，应用也应在 APP_ENV=production 时强制校验 SECRET_KEY、POSTGRES_PASSWORD、CORS_ORIGINS 等关键配置，缺失或仍为默认值时直接退出。
改进：加入生产配置启动检查；使用 Secret Manager 或 Docker secrets；日志中禁止打印连接串；数据库用户采用最小权限；Redis、PostgreSQL 不暴露公网端口；生产启用 HTTPS、HSTS、Secure/HttpOnly/SameSite Cookie 或短期 Bearer token。
3.4 数据库 create_all 不能替代迁移
main.py 的 lifespan 在启动时执行 Base.metadata.create_all(bind=engine)。这适合原型，不适合生产：不会记录迁移版本、不会安全变更字段、无法回滚，多个实例同时启动时也缺乏明确的迁移协调。
改进：正式使用 Alembic；CI 执行 upgrade head；发布流程先备份、迁移、健康检查、再切流；为题库和学习记录设计向后兼容的 schema 版本。

九、测试与质量门禁建议
建议把“能构建”升级为“可证明地正确”。
后端：pytest + httpx，覆盖认证、家庭隔离、学生 CRUD、题库筛选、导入校验、OCR 状态机、确认权限、错误码。
数据库：每个测试使用临时数据库；迁移从空库执行；种子数据只在显式 fixture 中加载。
前端：Vitest 测试 API 错误、角色路由、按钮 loading、空状态；Playwright 测试学生练习和家长确认两条关键路径。
安全：Bandit/ruff、pip-audit、npm audit、Trivy 镜像扫描、秘钥扫描；CI 阻止默认密钥和高危依赖。
契约：从 OpenAPI 生成 TypeScript 类型；前后端接口变更必须先改 schema；检查文档接口与实际路由一致。
可观测性：结构化日志、request_id、错误追踪、任务耗时、OCR 置信度、推荐采纳率；不要记录学生原始隐私内容。
十、可直接拆分的开发任务清单
十一、最终结论
这套代码最值得保留的是：产品边界意识、三角色工作台的视觉方向、教材/题库/证据/AI 报告的整体产品叙事，以及把事实、判断和数据不足区分开的理念。最需要尽快改变的是：不要把前端角色切换当作权限；不要让 demo、seed 和生产入口混在一起；不要在没有认证、迁移和测试的情况下接入真实学生数据。
建议下一轮不要继续堆叠 OCR 或 AI 展示功能，而是先完成 P0-01 至 P0-04，再实现一条真实、可审计、可复测的“家长上传成绩 → 确认 → 学生练习 → 判题 → 错题 → 复测 → 报告”闭环。这样比继续增加首页卡片更能提升产品可信度和长期可维护性。
